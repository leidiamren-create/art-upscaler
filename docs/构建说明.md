# 从源码构建与准备 Release

## 1. 源码运行与测试

使用 Python 3.12 或更新版本建立虚拟环境，安装 `requirements.txt`。运行：

```sh
python -m unittest discover -s tests -p "test_*.py" -v
node tests/test_ui.js
python app.py --engine /path/to/engine
```

Node.js 只用于前端逻辑测试，运行程序不需要 Node.js。本仓库没有 GitHub Actions 配置，不会因上传源码自动运行 CI 或发布。

## 2. 生成纯源码 ZIP

```sh
python scripts/build_source.py
```

输出到 `dist/art-upscaler-v0.1.1-source.zip`，旁边生成 SHA-256 文件。脚本只打包 `SOURCE_FILES.txt` 中逐个列明的文件，并拒绝符号链接、越界路径、二进制、运行日志及常见密钥格式；固定 ZIP 时间戳和文件顺序。每次变更文件集合后需复核并更新清单。

这个 ZIP 不带运行时和模型，不是便携版。文件校验和用于检查一致性，并不是代码签名、恶意软件检测或权利证明。

## 4. 组装工作目录

在一个全新的暂存目录下创建 `ArtUpscaler/`：

- 根目录：`app.py`、`core.py`、`ui.html`、`启动素材清晰工坊.cmd`、`LICENSE`、`README.md`、`THIRD_PARTY_NOTICES.md`、`docs/` 和 `licenses/`
- `runtime/`：将官方 Python 嵌入包解压于此；将对应 Pillow wheel 作为 ZIP 解压于同一目录，保留 `PIL/`、依赖文件及完整 `.dist-info/`，包括许可证
- `runtime/python314._pth`：内容为下面三行；不要启用全局 `site-packages`
- `engine/`：官方引擎的 `waifu2x-ncnn-vulkan.exe`、所需原始 DLL、上游许可，以及 `models-cunet/` 和 `models-upconv_7_anime_style_art_rgb/` 中的 `.bin` / `.param`

```text
python314.zip
.
..
```

本版本不使用 SQLite；先前便携包省略 `_sqlite3.pyd` 和 `sqlite3.dll`。不得省略 Python/Pillow 许可、Pillow 依赖库、引擎所需的模型文件或运行库。不复制上游样例图片、未知可执行程序、测试输出、缓存、素材或日志。

MSVC 运行库存在独立分发条件。公开二进制前先核对 `THIRD_PARTY_NOTICES.md`、Python 许可中的 Microsoft 条款以及适用于 `vcomp140.dll` 的 Microsoft 分发要求；不能仅凭根 MIT 文件作全包授权声明。若无法确认，先只发源码和官方依赖下载指引。

## 5. 分成三个 Release 附件

每个 ZIP 中都从同一个 `ArtUpscaler/` 前缀开始，确保解压可以合并：

1. 01 主程序包：根目录应用、使用说明、完整许可及 `runtime/`，例如 `01-素材清晰工坊-主程序-v0.1.1.zip`
2. 02 引擎和放大模型包：`engine/` 直属的可执行文件、运行依赖、上游说明，以及 `models-cunet/` 中文件名包含 `scale` 的模型；附相关第三方许可
3. 03 其余模型包：`models-cunet/` 中剩余的单倍降噪模型和完整 `models-upconv_7_anime_style_art_rgb/`，附模型 MIT 许可

如采用其他分包方式，所有模型文件仍须齐全，文件名与说明必须同步。三个包放 GitHub Release 附件，不提交进 Git 历史。小更新只适用于已装完整旧版的用户，不能代替首次安装三包。

生成 SHA-256 清单时，只记录相对文件名和校验值。公开发布前解压三包到新目录，运行 ZIP 完整性检查，核对无文件丢失或被不同包覆盖成不同内容，再完成 Windows 启动、先试一张、取消/重跑及透明图片验收。没有验收的项目应在 Release 中明确列为未验证。

当前仓库提供可重复的源码打包脚本及便携版组装流程；不声称已经用此流程重新生成并实机验证了 Windows 二进制，也不承诺 ZIP 与先前便携包逐字节相同。
